# Cognitive Architectures for Language Agents（CoALA）

## 摘要

这是普林斯顿大学 Sumers、Yao、Narasimhan、Griffiths 等人提出的一篇概念框架论文（发表于 TMLR 2024 年 2 月，arXiv 首版 2023 年 9 月）。论文借鉴认知科学与符号 AI 的历史——特别是 production system（产生式系统）和 Soar 等经典认知架构——提出 CoALA（Cognitive Architectures for Language Agents）框架，用以组织和设计 language agent。CoALA 沿三个维度刻画一个 agent：模块化的信息存储（working memory 与 episodic / semantic / procedural 三类长期记忆）、结构化的动作空间（外部 grounding 动作与内部 retrieval / reasoning / learning 动作）、以及通用决策流程（proposal → evaluation → selection → execution 的循环）。论文用该框架回溯性地整理了 SayCan、ReAct、Voyager、Generative Agents、Tree of Thoughts 等代表性工作，并前瞻性地指出可执行的研究方向。需要说明的是，这是一篇框架性 / 综述性论文，本身不包含新的实验或 benchmark。

## 要点

**核心类比：LLM 即概率化的 production system**

- 论文把 LLM 类比为 production system：产生式规则定义「字符串 X 可改写为 XW」，LLM 则定义给定 prompt X 时各种续写 Yi 的概率分布 P(Yi|X)，每次调用相当于采样一条产生式。
- 由此，prompt engineering（few-shot、检索增强、self-critique 等）可以被统一理解为在 LLM 这个「概率产生式系统」之上施加 control flow——这正是经典认知架构为产生式系统所做的事情，构成把认知架构引入 LLM agent 设计的动机。

**框架三维度之一：记忆（memory）**

- LLM 本身是无状态的，agent 需要显式的记忆模块。CoALA 区分 short-term working memory 与三类 long-term memory：episodic（存过往经历 / 轨迹）、semantic（存关于世界与自身的知识）、procedural（存 LLM 权重中的隐式知识与 agent 代码中的显式知识）。
- Working memory 被定义为一种跨 LLM 调用持久存在的数据结构，是连接 LLM、长期记忆与 grounding 接口的中央枢纽：每次调用时从 working memory 中取出子集合成 prompt，输出再被解析回 working memory 的变量。这比「把 LLM 上下文窗口当工作记忆」的用法更一般。

**框架三维度之二：动作空间（action space）**

- 动作分为外部与内部两类。外部动作即 grounding：与物理环境（机器人）、人类对话、数字环境（游戏、API、网站、代码执行）交互。
- 内部动作按访问的记忆类型与读写方向分解为三种：retrieval（从长期记忆读入 working memory）、reasoning（用 LLM 读写 working memory，产生新信息）、learning（写入长期记忆，包括更新 episodic / semantic 记忆、微调 LLM 参数、甚至改写 agent 自身代码）。
- 论文特别提醒：向 procedural memory 写入（即 agent 修改自身代码）风险显著高于写 episodic / semantic 记忆，容易引入 bug 或使 agent 偏离设计者意图。

**框架三维度之三：决策流程（decision making）**

- 决策被结构化为循环执行的 decision cycle，类比程序的 main 主循环：在 planning 阶段用 reasoning 和 retrieval 提出（proposal）、评估（evaluation）候选动作并选择（selection），然后执行（execution）选中的 grounding 或 learning 动作，获得观察后进入下一循环。
- 论文指出当时大多数 agent 只做了「提出一个动作」，更复杂的 propose-evaluate-select 流程（如 Tree of Thoughts 的 BFS/DFS、RAP 的 MCTS）才刚刚开始出现。

**案例整理（论文 Table 2）**

- SayCan：仅 procedural memory（LLM + 学到的 value function），551 个固定 grounding 技能，只做 evaluation，相当于单步规划器。
- ReAct：无长期记忆，动作空间为 reasoning + grounding，决策循环固定为「先 reason 再 act」，是同时利用内部与外部动作的最简 agent。
- Voyager：具备全部四类动作，长期 procedural memory 存代码技能库，learning 表现为把验证过的技能写入技能库。
- Generative Agents：具备全部四类动作，episodic memory 存事件流，通过 reasoning 生成 reflection 写入 semantic memory。
- Tree of Thoughts：只有一个外部动作（提交最终答案），无长期记忆，但决策流程最复杂（迭代 propose-evaluate-select + 树搜索）。

**可执行建议（论文第 6 节）**

- 模块化：像 OpenAI Gym 之于 RL 那样，为 language agent 建立标准化的 Memory / Action / Agent 抽象，降低学术界与工业界的重复建设。
- 长期记忆要超越「只读的检索增强」：memory-augmented agent 能自主读写自生成内容，为 lifelong learning 打开空间。
- 学习要超越 in-context learning 与 finetuning：包括写经验、写知识、写代码；修改与删除（unlearning）在当时几乎无人研究。
- 动作空间的安全性：learning 动作（尤其是 procedural 修改）可能造成内部伤害，grounding 动作可能造成外部伤害，需要为最坏情形做动作空间的规约与消融。

## 与本库的关系

这篇论文是本库 [[agent-memory]] 子方向的重要理论来源之一：它给出的「working memory + episodic / semantic / procedural 长期记忆」四分法，是讨论 agent 记忆时最常用的概念词汇表，MemGPT、Generative Agents、Voyager 等被 [[agent-memory]] 页引用的系统都可以套进这个分类。

用 [[agent-harness]] 的六组件语言来翻译，CoALA 的各个概念有清晰的对应关系：

- CoALA 的 working memory 及「从 working memory 合成 prompt、把输出解析回变量」的机制，对应 [[context-manager]] 所管的上下文组装；其「超越 prompt engineering 的结构化 reasoning」主张与 [[context-engineering]] 的立场一致。
- CoALA 的长期记忆模块（episodic / semantic / procedural）是 [[state-artifact-store]] 的记忆面向——procedural memory 中的「agent 代码」尤其对应工件与轨迹持久化。
- CoALA 的 decision cycle（proposal-evaluation-selection-execution 循环）对应 [[control-loop]]。
- CoALA 的 grounding 动作（物理 / 对话 / 数字环境）对应 [[action-interface]]。

值得注意的是视角差异：CoALA 从认知架构传统出发，把 LLM 放在经典 agent 结构里；[[agent-harness]] 从工程运行时出发，把模型之外的一切基础设施当作设计对象。两者覆盖的概念高度重叠（记忆、动作、决策循环），可以互为参照系。

## 可质疑之处

- **没有新实验。** 本文是概念框架 + 回溯性综述，所有经验论断（如「Voyager 的技能库带来更好的探索与泛化」）均转引自被综述的原文，框架本身的描述效力建立在作者选取的五个案例上，是否覆盖后续 agent 形态需要交叉验证。
- **记忆分类是类比而非论证。** episodic / semantic / procedural 三分法借自心理学与 Soar，对 LLM agent 是否是最合适的分解方式，论文未给出实证检验；例如「 reflection 写入 semantic memory」与「原始事件留在 episodic memory」的边界在实践中并不稳定（待验证）。
- **内外边界问题由作者自己提出但未解决。** 论文第 7 节承认「Wikipedia 算内部 semantic memory 还是外部数字环境」这类问题没有唯一答案，只给出「可控性与耦合度」的判据，实际归类仍有主观空间。
- **框架时效性。** 作者自己承认长上下文窗口可能降低长期记忆模块的重要性、更强的模型可能把 CoALA 的机制内化到参数中（「GPT-N」思想实验）；该框架基于 2023 年的模型能力，对当前模型的适用程度待验证。
- **自我修改的风险只被指出、未被解决。** 论文反复强调 agent 改写自身 procedural memory（代码）的风险，但未提出任何验证或治理机制，这部分在本库属于 [[verification-governance]] 讨论的范畴。

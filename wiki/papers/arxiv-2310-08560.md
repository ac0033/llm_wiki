# MemGPT: Towards LLMs as Operating Systems

- 一手来源：https://arxiv.org/abs/2310.08560 （arXiv:2310.08560v2，2024-02-12；UC Berkeley，Packer 等）
- 代码与数据：https://research.memgpt.ai

## 摘要

论文针对 LLM 固定长度 context window 无法支撑长对话和长文档分析的问题，提出 virtual context management（虚拟上下文管理）：借鉴传统操作系统中虚拟内存分页的思想，把 context window 当作受限的"物理内存"，通过 LLM 自己发起的 function call 在 context 与外部存储之间换入换出数据，从而制造"无限上下文"的假象。基于这一思想作者实现了 MemGPT（MemoryGPT），一个 OS 风格的分层记忆系统，包含 main context（类比 RAM）与 external context（类比磁盘）两级存储，以及事件驱动的控制流。实验在两个受限于上下文长度的领域验证：document analysis 中 MemGPT 能分析远超底层模型 context window 的文档；multi-session chat 中 MemGPT 能在长期交互里保持记忆、一致性与个性化。

## 要点

### 核心贡献

- 提出 virtual context management 技术：不改模型、不扩 context window，而是用操作系统的分层记忆与分页机制管理上下文，让 fixed-context LLM 处理无界上下文。
- 实现 MemGPT 系统，并在两个领域（multi-session chat、document analysis）系统评估，同时发布了增强版 MSC 数据集、nested KV retrieval 数据集和 20M 篇 Wikipedia 文章的 embedding 数据集。

### 方法：MemGPT 的体系结构

- **两级记忆**：main context 即 prompt tokens（类比主存），分为三段——只读的 system instructions（描述控制流、记忆层级与函数用法）、可读写的 working context（固定大小，只能通过 function call 写入，用于存放用户事实、偏好与 persona）、以及 FIFO queue（滚动消息历史，队首存放被驱逐消息的 recursive summary）。external context（类比磁盘）包括 recall storage（完整消息历史数据库，由 queue manager 写入）与 archival storage（可读写数据库，存任意长度文本）。
- **Queue manager 与溢出控制**：当 prompt tokens 超过 warning token count（例如 context window 的 70%）时插入 "memory pressure" 系统消息，提醒 LLM 主动把重要信息存入 working context 或 archival storage；超过 flush token count（约 100%）时驱逐一部分消息（例如 50%），并基于旧 recursive summary 与被驱逐消息生成新的 recursive summary。被驱逐的消息仍永久留在 recall storage，可通过 function call 检索回来。
- **自我导向的记忆管理（self-directed editing）**：记忆的写入与检索完全由 LLM 自主决定——system instructions 里给出记忆层级说明和函数 schema，LLM 输出被解析为 function call 执行，执行结果（包括运行时错误）反馈回 LLM，形成反馈回路。检索接口带 pagination，防止单次检索结果撑爆 context window。
- **事件驱动控制流与 function chaining**：用户消息、系统告警、定时事件等都作为 event 触发 LLM 推理；LLM 可在输出中设置 `request heartbeat=true` 标志，请求函数执行完后立即再次推理，从而把多次 function call 串联起来完成多步检索，不设该标志则让出控制权（yield）等待下一个外部事件。

### 实验设置与结果

- **底层模型**：GPT-4（gpt-4-0613，8k context）、GPT-4 Turbo（gpt-4-1106-preview，128k）、GPT-3.5 Turbo（gpt-3.5-turbo-1106，16k），每组均对比加不加 MemGPT。
- **Deep Memory Retrieval（DMR，一致性）**：基于 Multi-Session Chat（MSC）数据集扩展出第 6 个 session 的问答对；基线只能看到前 5 个 session 的有损摘要，MemGPT 则保存完整历史但须通过分页检索取回。MemGPT 显著提升所有基座模型：GPT-4 准确率从 32.1% 提升到 92.5%，GPT-4 Turbo 从 35.3% 到 93.4%，GPT-3.5 Turbo 从 38.7% 到 66.9%（ROUGE-L recall 同步提升，见原文 Table 2）。
- **Conversation opener（engagement）**：评估 agent 利用历史会话写开场白的能力，用与 gold persona / 人工开场白的相似度（CSIM 指标）打分；MemGPT 生成的开场白达到甚至超过人工撰写的水平（原文 Table 3）。
- **多文档 QA**：沿用 Liu et al.（2023a，即 Lost in the Middle）的 retriever-reader 设置，问题来自 NaturalQuestions-Open（采样 50 题），检索用 text-embedding-ada-002 余弦相似度；MemGPT 侧把整个 Wikipedia（2018 年末 dump）存入 archival storage（PostgreSQL + pgvector，HNSW 索引），由 LLM 自主分页查询。结果：MemGPT 的准确率不随检索文档数 K 增大而下降，突破了固定上下文基线"上限即 retriever 性能"的限制；但 GPT-3.5 因 function calling 能力弱而显著退化，GPT-4 表现最好。
- **Nested KV retrieval（多跳检索，新提出任务）**：140 对 UUID key-value（约 8k token），value 本身可能是 key，嵌套层数 0–4，采样 30 种顺序。GPT-3.5 在 1 层嵌套时准确率即掉到 0%，GPT-4 / GPT-4 Turbo 到 3 层时为 0%；MemGPT + GPT-4 不受嵌套层数影响，是唯一能稳定完成 2 层以上嵌套的方法。值得注意的是 MemGPT + GPT-4 Turbo 反而差于 MemGPT + GPT-4。

### 结论

作者认为 OS 的分层记忆管理与中断等机制可以在不改变固定 context window 的前提下释放 LLM 潜力；未来方向包括把 MemGPT 用于更多无界上下文场景、接入更多存储层技术、改进控制流与记忆管理策略。

## 与本库的关系

- 本论文是本库 [[agent-memory]] 子方向的核心文献：working context / recall storage / archival storage 的三层划分，是 [[context-manager]] 组件最典型的参照设计之一——MemGPT 把"什么放进 prompt"从静态拼接变成了 LLM 自主决策的运行时过程。
- archival storage 与 recall storage 落到 PostgreSQL/pgvector 的做法，对应 [[state-artifact-store]] 组件：持久状态放在 context 之外，按需分页取回。
- 事件驱动 + `request heartbeat` 的 function chaining 是 [[control-loop]] 的一种具体实现：LLM 可以连续多步行动而不必每步都让出控制权，这与 [[react]] 的交错推理-行动思路相呼应（论文 related work 也明确提到 agent 在执行函数时可以 "plan out loud"）。
- 整个系统是 [[agent-harness]] 视角下的典型案例：LLM 处理器本身不变，harness（queue manager、function executor、事件解析器）围绕它提供记忆与控制流，是 [[context-engineering]] 的早期系统性工作。
- 实验方法上大量借用 [[arxiv-2307-03172]]（Lost in the Middle）的 QA 与 KV retrieval 任务，并以此为论据说明单纯扩大 context window 收益有限。

## 可质疑之处

- **评测高度依赖 OpenAI 模型与 LLM judge**：所有实验均基于 GPT-3.5/4 系列，DMR 与文档 QA 的正确性由 GPT-4 充当 judge 判定，论文未给出人工核验 judge 一致性的细节（仅引用 Zheng et al. 2023 说明 GPT-4 judge 与人类评估有较高一致性）；对开源模型是否同样有效待验证。
- **DMR 的 QA 对由另一个 LLM 生成**（"see Appendix"），数据质量与难度分布依赖生成模型，可能放大对检索友好问题的比例；待验证。
- **文档 QA 任务中 MemGPT 常提前停止翻页**：论文自己观察到 MemGPT 理论上可通过分页遍历整个检索排序，但实际经常在翻完之前停止，说明"自主记忆管理"的可靠性仍受底层模型 function calling 能力制约（GPT-3.5 上退化明显，GPT-4 Turbo 上 nested KV 反而更差的原因论文未深入解释）。
- **延迟与成本未量化**：多步 function call 链意味着单条用户消息可能触发多次 LLM 推理，论文没有报告时延与 token 开销，实际部署成本待验证。
- **recursive summary 的有损性**：FIFO queue 驱逐后只留递归摘要，若 LLM 在 memory pressure 告警时未能及时把关键信息写入 working context，信息虽在 recall storage 但能否被后续查询命中取决于检索质量，论文未对此失败模式做定量分析。

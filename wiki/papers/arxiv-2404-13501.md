# A Survey on the Memory Mechanism of Large Language Model based Agents

- 一手来源：https://arxiv.org/abs/2404.13501 （arXiv:2404.13501v1，2024-04-21；中国人民大学高瓴人工智能学院 + 华为诺亚方舟实验室，Zeyu Zhang 等）
- 配套仓库（论文清单持续更新）：https://github.com/nuster1128/LLM_Agent_Memory_Survey

## 摘要

这是第一篇系统综述 LLM-based agent 记忆机制的论文（作者自称 to our knowledge 为首篇）。论文围绕三个问题组织：记忆「是什么」（给出狭义与广义两种定义，并把 agent-环境交互形式化为 task / trial / step 三层结构）、「为什么需要」（从认知心理学、self-evolution、agent 应用三个视角论证）、「如何实现与评测」（从记忆来源、记忆形式、记忆操作三个维度分类已有工作，并给出直接评测与间接评测两类评测框架）。论文还梳理了 role-playing、社会模拟、个人助理、开放世界游戏、代码生成、推荐、垂直领域专家系统等记忆增强 agent 应用，并讨论了 parametric memory、多智能体记忆、lifelong learning、humanoid agent 四个未来方向。

## 要点

### 核心贡献

- 形式化定义 agent 记忆，并给出统一记忆迭代公式：a_{t+1} = LLM{R(P(M_{t-1}, W({a_t, o_t})), c_{t+1})}，即「写入 W → 管理 P → 读取 R」三个操作驱动 agent 的下一步动作；已有工作可视为对 W/P/R 的不同实例化（例如 Generative Agents 的 R 综合 relevance、recency、importance 三个准则，P 用 reflection 实现）。
- 提出三维分类法：记忆来源（sources）× 记忆形式（forms）× 记忆操作（operations），并用三张表格逐一标注约 30 个代表性模型在各维度上的取舍（Table 1-3）。
- 给出直接评测（subjective / objective）与间接评测（conversation、multi-source QA、long-context、success rate 等任务）的记忆评测框架。

### 记忆的狭义与广义定义

- **狭义记忆**：只包含同一 trial 内的历史信息 ξ_t = {a_1, o_1, ..., a_{t-1}, o_{t-1}}；trial 结束后记忆清空。
- **广义记忆**：信息可来自三个来源——trial 内历史、跨 trial 历史（含同一任务此前的失败 trial），以及 agent-环境交互之外的外部知识（如 Wikipedia、工具 API）。
- agent-环境交互被拆为三个阶段：感知信息写入记忆 → 加工已存信息 → 基于加工后的记忆采取下一步动作，三阶段分别对应写入、管理、读取操作。

### 记忆来源（Section 5.1）

- **Inside-trial information（trial 内信息）**：几乎所有工作都使用，与当前任务最相关；但只靠它无法跨任务积累经验。
- **Cross-trial information（跨 trial 信息）**：以 Reflexion、ExpeL、Synapse、Retroformer 为代表，把成功/失败经验以 verbal 形式存入，可视为长期记忆，支撑 agent 自我演化。
- **External knowledge（外部知识）**：以 ReAct、GITM、CodeAgent、ChatDoctor 为代表，通过 API/工具实时获取 Wikipedia、领域数据库等知识，突破 agent 亲历经验的边界，但引入隐私、安全性与信息可靠性问题。

### 记忆形式（Section 5.2）

- **Textual form（文本形式，当前主流）** 细分为四种：(1) complete interactions——把完整交互历史拼进 prompt，受限于 context window 长度，且存在位置偏置（引 Lost in the Middle，即 [[arxiv-2307-03172]]，指出长上下文中不同位置的文本利用率不均）；(2) recent interactions——按 Principle of Locality 只保留最近窗口（如 SCM 的 flash memory、MemGPT 的 working context），但会丢失远期关键信息；(3) retrieved interactions——按 relevance/importance 检索 top-K（如 Generative Agents、MemoryBank 用双塔检索 + FAISS、RET-LLM 用 LSH、ChatDB 用 SQL），依赖检索精度与效率；(4) external knowledge——工具调用获取的外部文本知识。
- **Parametric form（参数化形式）** 分为 fine-tuning（SFT 注入领域知识，如 Character-LLM、Huatuo、DoctorGLM；存在过拟合与灾难性遗忘风险，且成本高、只适合离线场景）与 memory editing / knowledge editing（精准修改个别事实，如 MAC、MEND、KnowledgeEditor、PersonalityEdit；适合小规模在线调整）。
- **两种形式对比**：文本记忆写入便宜、可解释，但读取时占 context、推理成本高；参数化记忆不占 context、读取零额外开销、信息密度高，但写入（训练）昂贵、不可解释。结论：对话类、需近期交互的任务适合文本记忆；知识量大、相对稳定的任务适合参数化记忆。

### 记忆操作（Section 5.3）

- **Writing（写入）**：决定记什么——存原始信息还是提炼后的摘要。例：TiM 抽取实体关系存结构化数据库并分组；SCM 用 memory controller 决定何时写；MemGPT 的写入完全由 LLM self-directed；MemoChat 把每段对话摘要为 memo 作为索引键。
- **Management（管理）**：对已有记忆做三类加工——reflection（生成高层抽象，如 Generative Agents、MemoryBank、GITM）、merging（合并冗余条目）、forgetting（遗忘不重要/过时信息，如 MemoryBank 的类 Ebbinghaus 遗忘机制）。设计多借鉴人脑记忆机制。
- **Reading（读取）**：按当前 context 的相关性取出记忆。例：ChatDB 生成 SQL（Chain-of-Memory）查询；MPC 提供「忽略某些记忆」的 CoT 示例；ExpeL 用 FAISS 取 top-K 成功轨迹。文本记忆的读取多用相似度 + 辅助信息；参数化记忆的读取是隐式的（直接用更新后的参数推理）。

### 记忆评测（Section 6）

- **直接评测**：把记忆模块当独立组件评测。Subjective 维度常用 coherence（召回记忆是否与当前语境自然契合）与 rationality（是否合理），靠人工评分或两两对比；Objective 维度包括 result correctness（基于记忆回答预设问题的准确率）、reference accuracy（检索到的记忆与 ground truth 的 F1）、以及 time & hardware cost（写入/管理的 adaptation time、读取的 inference time、峰值 GPU 显存）。
- **间接评测**：通过端到端任务反推记忆有效性——conversation（consistency、engagement，如 GPT-4 打分、SCE-p、CSIM 指标）、multi-source QA（检验多来源记忆的整合与矛盾处理）、long-context 应用（passage retrieval、长文本摘要）、success rate（AlfWorld、Minecraft）与 exploration degree 等。
- **作者的判断**：间接评测有现成 benchmark、易做，但任务表现可归因于记忆之外的诸多因素；直接评测更可靠，然而「目前没有为 agent 记忆模块量身定制的开源 benchmark」（原文 Section 6.3 明确承认这一点）。

### 应用与局限

- 应用面（Section 7）：role-playing 与社会模拟（记忆保证角色一致性）、个人助理（以检索式文本记忆为主）、开放世界游戏（经验复用 + 外部 Wiki）、代码生成（对话连续性 + 历史错误检索）、推荐（用户画像与偏好的个性化记忆）、医药/金融/科学等专家系统（领域知识注入的时效性与规模是主要挑战）。
- 未来方向（Section 8）：parametric memory 的效率与可解释性、multi-agent 场景下的记忆同步/通信/信息不对称、基于记忆的 lifelong learning（需要处理记忆的时间性与大规模存储-遗忘机制）、humanoid agent（记忆需模拟人类的不完美性——记忆扭曲、遗忘、知识边界）。

## 与本库的关系

- 本页是本库 [[agent-memory]] 概念与子方向 [[agent-memory-context]] 的核心分类参照：「写入 / 管理 / 读取」三段操作分解是该方向页组织文献的主框架之一。
- 与 [[arxiv-2309-02427]]（CoALA）互补：CoALA 按认知科学把记忆分为 working / episodic / semantic / procedural 四类（按「存什么」分），本综述按「信息从哪来、怎么存、怎么操作」分（sources / forms / operations），两者是正交的分类轴，可交叉使用。
- [[arxiv-2310-08560]]（MemGPT）在本综述的三张分类表中反复出现：来源上只用 inside-trial 信息、形式上属 recent + retrieved 文本记忆、操作上写入由 LLM self-directed——是把「记忆管理交给模型自己」路线的代表案例。
- 本综述在讨论 complete interactions 的缺陷时引用 [[arxiv-2307-03172]]（Lost in the Middle）作为长上下文位置偏置的证据，说明「把所有历史直接拼进 prompt」不是可行的记忆方案。
- 时间线上，本综述（2024-04）早于 [[arxiv-2502-12110]]（A-Mem）与 [[arxiv-2507-13334]]（Context Engineering 综述）：A-Mem 的「记忆自动演化」可视为对本综述 management 操作中 reflection/merging 的自动化推进；Context Engineering 综述则把记忆放入更大的上下文组装框架中。
- 从 [[agent-harness]] 视角看，本综述的 textual memory + retrieval 组合正是 [[context-manager]]（读取时决定哪些记忆进 prompt）与 [[state-artifact-store]]（记忆落在 FAISS / SQL 数据库等外部存储）两个组件的分工；其评测框架与 [[agent-evaluation]] 相关。

## 可质疑之处

- **覆盖时效性**：v1 发布于 2024-04，此后涌现的记忆系统（如 A-Mem、Mem0、Zep、HippoRAG 等）均未覆盖；「textual 为主流、parametric 研究不足」的格局判断是否仍然成立，待验证。
- **分类边界有重叠**：论文自己承认 R 与 P 在部分工作中是同一个函数（如 Reflexion），cross-trial 信息与「写入长期存储的 inside-trial 信息」在实际系统中也难以区分；三维分类法是描述性框架而非互斥划分。
- **评测框架停留在综述层面**：论文整理了评测维度（coherence/rationality、F1、时延等），但没有给出可执行的统一 benchmark，也明确指出当时不存在针对记忆模块的开源 benchmark——这一空白是否已被后续工作（如 LongMemEval、LoCoMo 等）填补，待验证。
- **应用场景多为单篇工作罗列**：Section 7 对各应用的记忆设计做了总结性洞察（如 role-playing 需记忆与角色一致），但缺少跨应用的量化对比，「记忆是关键组件」的论断主要靠定性论证。
- **「首篇记忆综述」的自述**：作者声明 to our knowledge 为首篇，该声明未经过系统检索论证，同期可能有相近综述，待验证。

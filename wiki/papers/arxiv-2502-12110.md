# A-Mem: Agentic Memory for LLM Agents

- 一手来源：https://arxiv.org/abs/2502.12110（PDF 版本为 arXiv:2502.12110v11，2025-10-08）
- 作者：Wujiang Xu、Zujie Liang、Kai Mei、Hang Gao、Juntao Tan、Yongfeng Zhang（Rutgers University / AIOS Foundation）
- 代码：评测版 https://github.com/WujiangXu/AgenticMemory ；生产版 https://github.com/WujiangXu/A-mem-sys

## 摘要

本文提出 A-MEM，一个面向 LLM agent 的 agentic memory（智能体式记忆）系统，目标是让 agent 在不依赖预定义记忆操作与固定工作流的前提下获得长期交互能力。设计借鉴 Zettelkasten（卡片盒笔记法）：每条新记忆被构造成带上下文描述、关键词、标签等结构化属性的原子笔记，再由 LLM 分析历史记忆并自动建立语义链接；新记忆的加入还会触发"记忆演化"——更新已有历史记忆的上下文表示与属性，使记忆网络随经验持续精炼。作者在 LoCoMo 与 DialSim 两个长期对话数据集上、跨六个 foundation model 做了评测，A-MEM 相对 LoCoMo、ReadAgent、MemoryBank、MemGPT 等基线取得了更好的结果，同时把每次问答的 prompt 长度从约 16,900 token 压到约 1,200–2,500 token。

## 要点

**问题定位**

- 现有 agent 记忆系统（MemoryBank、MemGPT、Mem0 等）要求开发者预定义存储结构、写入时机和检索时机；即便引入图数据库，预定义 schema 也限制了跨任务的适应性，无法随知识增长产生新的组织方式。

**方法（四个环节）**

- Note Construction：每次交互生成一条原子记忆笔记 `mi = {ci, ti, Ki, Gi, Xi, ei, Li}`——原始内容、时间戳、LLM 生成的关键词/标签/上下文描述、稠密向量（用 text encoder 对内容+关键词+标签+上下文拼接编码）、以及链接集合。
- Link Generation：新笔记入库时先用 embedding 余弦相似度检索 top-k 历史记忆，再让 LLM 判断应与哪些建立链接（而非纯靠相似度阈值），形成 Zettelkasten 式的互联"盒子"，一条记忆可同时属于多个盒子。
- Memory Evolution：新记忆入库后，对其近邻历史记忆，由 LLM 决定是否更新其上下文描述、关键词和标签，演化后的笔记替换原笔记，从而让记忆网络随新经验涌现更高阶的模式。
- Memory Retrieval：查询时同样用 embedding 余弦相似度取 top-k；被检索到的记忆所在的"盒子"里相互链接的相似记忆也会被一并带出。

**实验设置**

- 数据集：LoCoMo（长期对话，平均 9K token、最多 35 个 session，共 7,512 个问答对，分 single-hop / multi-hop / temporal / open-domain / adversarial 五类）；DialSim（《老友记》等美剧衍生的长期多方对话 QA，1,300 个 session、约 35 万 token）。
- 基线：LoCoMo、ReadAgent、MemoryBank、MemGPT；指标为 F1 与 BLEU-1（附录另有 ROUGE-L、ROUGE-2、METEOR、SBERT Similarity）。
- 底座模型：GPT-4o-mini、GPT-4o、Qwen2.5-1.5B/3B、Llama 3.2 1B/3B 六个（附录补充 DeepSeek-R1-32B、Claude 3.0/3.5 Haiku）；embedding 统一用 all-minilm-l6-v2；检索默认 k=10。

**主要结果**

- LoCoMo 上：非 GPT 模型下 A-MEM 在所有类别一致优于全部基线；GPT 模型下 A-MEM 在 multi-hop 任务上优势明显（论文称至少两倍于需要复杂推理链的基线水平，如 GPT-4o-mini 下 multi-hop F1 27.02，temporal F1 45.85），但在 Open Domain、Adversarial 等依赖预训练知识做简单事实检索的类别上，LoCoMo/MemGPT 仍有个别领先。A-MEM 的平均排名在所有六个模型上均为第一（1.0–1.6）。
- DialSim 上：A-MEM 在所有指标上领先，F1 为 3.45（LoCoMo 2.55、MemGPT 1.18）。
- 消融（GPT-4o-mini）：同时去掉 link generation 与 memory evolution 后 multi-hop F1 从 27.02 跌到 9.65；只保留 link generation 时为 21.35，说明链接生成是基础、记忆演化提供进一步增益。
- 成本与扩展性：每次记忆操作约 1,200 token，相比基线的约 16,900 token 减少 85–93%，单次操作成本低于 0.0003 美元；记忆条目从 1,000 扩到 1,000,000 时检索耗时仅从 0.31µs 增至 3.70µs，存储随条目数线性增长、与基线相同。
- 超参分析：k 增大总体提升性能但在 30–40 之后趋于平稳甚至略降，提示上下文丰富度与噪声之间的权衡。
- T-SNE 可视化显示 A-MEM 的记忆 embedding 比无链接/无演化的基线呈现更紧凑的聚类结构。

## 与本库的关系

- 本文是 [[agent-memory]] 子方向的核心文献：把 agent 记忆从"预定义读写接口的存储组件"推向"自主组织、自主演化的记忆网络"，与 [[generative-agents]] 的 memory stream、MemGPT 的操作系统式分层记忆构成对照脉络。
- 在 [[agent-harness]] 的六组件视角下，A-MEM 同时承担两类职责：记忆库本身是 [[state-artifact-store]]（持久化交互历史与演化后的知识结构）；检索 top-k 记忆注入 prompt 的环节属于 [[context-manager]]（决定哪些历史进入上下文窗口）。其"每次操作约 1,200 token"的成本分析也直接回应了 context 预算问题。
- A-MEM 与 agentic RAG 的区别被作者明确界定：agentic RAG 的自主性在检索侧（何时检索、检索什么），知识库本身仍是静态的；A-MEM 的自主性在存储与演化侧。这对理解 [[context-engineering]] 中"动态上下文组装"与"静态知识注入"的分工有参考价值。

## 可质疑之处

- 评测仅覆盖长期对话 QA（LoCoMo、DialSim），没有涉及代码、工具使用等典型 agent 任务，"灵活通用的记忆系统"这一主张在其他任务类型上的有效性待验证。
- 所有结构化属性（关键词、标签、上下文描述）和链接、演化判断都由 LLM 生成，作者也在 Limitations 中承认组织质量受底座 LLM 能力影响；小模型上生成的描述质量是否会系统性地拖累记忆网络，论文未做隔离分析，待验证。
- 成本数字"每次记忆操作约 1,200 token、低于 0.0003 美元"把写入侧（note construction、link generation、memory evolution 共多次 LLM 调用）与读取侧合并表述，各环节各自的 token 拆分未在正文中给出，待验证。
- 检索时间使用 µs 级数字（百万条目 3.70µs），未说明检索索引实现细节（是否近似最近邻、是否含 LLM 调用），纯向量检索之外的 link/evolution 开销未计入该表，待验证。
- DialSim 上所有方法的绝对分数都很低（F1 均在 3.5 以下），相对提升比例虽大，但该指标下的绝对水平是否可用需谨慎解读。
- 记忆演化会改写历史记忆的上下文与属性，长期运行下是否存在"漂移"（错误演化累积污染记忆库）没有负向对照实验，待验证。

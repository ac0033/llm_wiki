# A Survey of Context Engineering for Large Language Models

- 一手来源：https://arxiv.org/abs/2507.13334（v2，2025-07-21，arXiv:2507.13334）
- 作者团队主要来自中科院计算技术研究所（ICT, CAS）、UC Merced、北京大学、清华大学等；代码仓库：https://github.com/Meirtz/Awesome-Context-Engineering

## 摘要

这是一篇系统综述（survey），作者通过分析超过 1400 篇研究论文，把 "Context Engineering"（上下文工程）正式定义为一门超越简单 prompt 设计的学科：系统化地为 LLM 优化推理时的信息载荷（information payload）。论文提出了一个统一分类法（taxonomy），把上下文工程拆成三个基础组件——Context Retrieval and Generation（上下文检索与生成）、Context Processing（上下文处理）、Context Management（上下文管理）——以及四类把这些组件集成进智能系统的实现——RAG、Memory Systems（记忆系统）、Tool-Integrated Reasoning（工具集成推理）、Multi-Agent Systems（多智能体系统）。论文的核心洞见是：当前模型在"理解复杂上下文"和"生成同等复杂的长文输出"之间存在根本性的不对称（comprehension-generation gap），这是该领域最关键的未解问题之一。

## 要点

**关键贡献**

- 给出 Context Engineering 的形式化定义：把上下文 C 从 prompt engineering 时代的静态字符串，重构为由装配函数 A 动态组装的结构化组件集合 C = A(c₁, c₂, ..., cₙ)，其中组件包括系统指令 c_instr、外部知识 c_know、工具定义 c_tools、持久记忆 c_mem、动态状态 c_state 和用户请求 c_query。
- 把上下文工程表述为一个优化问题：在上下文长度硬约束 |C| ≤ L_max 下，寻找一组上下文生成函数 F = {A, Retrieve, Select, ...}，最大化 LLM 输出的期望质量；并从信息论（检索最大化与目标答案的互信息）和贝叶斯上下文推断（推断最优上下文后验 P(C|query, History, World)）两个视角给出理论框架。
- 提出贯穿全文的分类法（Figure 1），将碎片化的 prompt engineering、RAG、memory、tool use、multi-agent 等研究领域统一到一个横向框架下，明确指出"RAG 是外部记忆的一种形式、工具使用是上下文获取的手段、prompt engineering 是编排这些组件的语言"这些此前隐含的关联。

**方法主体（分类法结构）**

- 基础组件之一 Context Retrieval and Generation：涵盖 prompt 生成技术与外部知识获取、动态上下文组装。
- 基础组件之二 Context Processing：长序列处理（Mamba、LongNet、FlashAttention、YaRN、StreamingLLM 等）、self-refinement（Self-Refine、Reflexion）、多模态与结构化上下文整合。
- 基础组件之三 Context Management：应对有限上下文窗口的根本约束，包括记忆层级与存储架构、上下文压缩（如 ICAE 的 4× 压缩、KV cache 管理）与优化策略。
- 系统实现之一 RAG：从模块化、agentic 到 graph-enhanced 架构（Self-RAG、GraphRAG、LightRAG、HippoRAG、RAPTOR 等）。
- 系统实现之二 Memory Systems：记忆按时间维度分为 sensory / short-term / long-term；按实现分为 parametric memory（参数内知识）、ephemeral activation memory（运行时状态，如 KV cache）和 plaintext memory（经 RAG 访问的明文存储）；代表系统包括 MemGPT（借鉴 OS 虚拟内存，在有限上下文与外部存储之间分页）、MemoryBank（基于 Ebbinghaus 遗忘曲线）、SCM、REMEMBERER、MemLLM、MemOS、A-MEM 等。
- 系统实现之三 Tool-Integrated Reasoning：function calling 机制与 agent-环境交互（Toolformer、ReAct、Gorilla、ToolLLM 等）。
- 系统实现之四 Multi-Agent Systems：通信协议（KQML、FIPA ACL、MCP、A2A、ACP、ANP）与编排机制（AutoGen、MetaGPT、CAMEL、CrewAI 等）。

**与 Memory / Context 直接相关的实证观察**

- "lost-in-the-middle" 现象：LLM 难以访问长上下文中部的信息，相关信息在开头或结尾时表现显著更好；在长 CoT 推理任务中，早期中间结果易被遗忘，性能相比无先验上下文最多可下降 73%（论文引用 [128, 1147, 381]）。
- LLM 天然无状态（stateless），跨交互维持状态必须依赖显式的管理系统；上下文管理面临两个相反方向的失败模式——context window overflow（超限遗忘）与 context collapse（上下文扩大后反而无法区分不同会话）。
- 记忆评测基准 LongMemEval（500 道题，覆盖信息抽取、时序推理、多会话推理、知识更新、拒答五种能力）显示，商用助手在长程交互中准确率下降约 30%；论文同时指出现有 benchmark 偏重事实与语义记忆，严重忽视 episodic memory（带时空情境的情景记忆）。

**评测与结论**

- 论文专章讨论评测（§6）：区分组件级评估与系统级集成评估，盘点 GAIA、SWE-Bench、WebArena、BFCL、LongMemEval 等 benchmark，并指出方法论层面的偏差与局限。
- 结论强调三点：理解-生成不对称是核心挑战；多种技术的组合产生超越单组件的协同能力；领域明显走向模块化与可组合性。未来方向包括统一理论基础（目前缺乏刻画上下文工程能力边界的数学框架）、O(n²) 注意力复杂度的高效替代、智能上下文组装、多智能体协调与安全部署。

## 与本库的关系

- 这篇综述是本库 [[context-engineering]] 概念页最系统的一手文献支撑：它把"上下文工程"从口号提升为有形式化定义（C = A(c₁, ..., cₙ)）和完整分类法的学科。
- 对 [[agent-memory]]：§4.3 与 §5.2 提供了记忆系统的完整分类坐标（sensory / short-term / long-term；parametric / activation / plaintext），MemGPT、MemoryBank、MemOS 等系统均可作为该概念页下的具体实例引用。
- 对 [[context-manager]]：论文的 Context Management 组件（§4.3）讨论的正是 context-manager 要解决的根本约束——有限窗口、lost-in-the-middle、压缩与层级存储，可作为该组件设计的理论依据。
- 对 [[state-artifact-store]]：论文把 c_mem（持久记忆）与 c_state（用户/世界/多智能体系统的动态状态）显式建模为上下文组件，对应 harness 中状态与工件持久化存储的职责；MemGPT 式的"上下文窗口 = 主存、外部存储 = 虚拟内存"类比与 state-artifact-store 的设计直觉一致。
- 对 [[agent-harness]]：论文的优化目标函数 F* = arg max E[Reward(P_θ(Y|C_F(τ)), Y*)] 本质上描述的就是 harness 的职责——在模型之外系统性优化喂给模型的信息；其四类系统实现（RAG、Memory、Tool、Multi-Agent）与 harness 的功能分层高度对应。
- 其他可关联页面：多智能体通信协议部分（MCP、A2A）关联 [[model-context-protocol]] 与 [[multi-agent-orchestration]]；Tool-Integrated Reasoning 关联 [[tool-use]]。

## 可质疑之处

- 形式化框架（优化目标、互信息最大化、贝叶斯上下文推断）是作者提出的概念性建模，论文自己也在 §7.1.1 承认"该领域目前缺乏统一的理论基础"，这些公式更多是组织视角而非可计算的方法——实际系统中如何优化 F，论文未给出可操作方案。
- "1400 篇论文"的筛选标准、检索时间范围与纳入/排除流程在正文中未见明确说明（待验证：是否有系统化的文献检索方法论章节），作为系统综述的可复现性存疑。
- 摘要声称这是 Context Engineering 的"first comprehensive and systematic review"，这一首创性声明难以验证（待验证），且"Context Engineering"作为术语在 2025 年被多家机构同时使用，概念边界尚不稳定。
- 论文时效性截止 2025 年 7 月，作者也在致谢中承认该领域发展极快、可能遗漏近期工作；对 2025 下半年之后的记忆系统与上下文技术演进无覆盖。
- lost-in-the-middle 导致性能下降 73% 等数字均转引自被综述的原始论文（[128, 1147, 381]），本综述未做独立实验验证，引用时应注意这些数字依赖原始论文的具体任务设定。
